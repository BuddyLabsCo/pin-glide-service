# Domain Docs

## Layout

This repository uses a single context:

- `GLOSSARY.md` at the repository root.
- ADRs under `docs/adr/`.

## Before exploring

Read the glossary and ADRs relevant to the area being explored.
If they do not exist, proceed silently. The domain-modeling skill creates
them when terminology or decisions are resolved.

## Vocabulary and decisions

Use the glossary's terms for domain concepts in issues, code, and proposals.
Reconsider unfamiliar terminology or record a real gap for domain-modeling.
Explicitly flag proposals that contradict an existing ADR, identifying the
ADR and explaining why the decision should be reconsidered.
